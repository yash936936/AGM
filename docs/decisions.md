## D-028 — Add explicit tenant/project-scoped retention purge
**Decision:** Add a core-library `MemoryStore.expire_before(ctx, cutoff, *, include_pinned=False)` operation returning an `ExpiryResult`. It selects memories by their source event's `created_at` timestamp, not by `valid_from` (which describes fact validity), and purges each eligible item through the existing hard-delete path. The sweep is scoped to the caller's tenant and project, processes older events first to avoid restoring an expired predecessor, and skips pinned memories unless `include_pinned=True`. Each item purge is its own atomic delete mutation/event; the sweep is not one all-or-nothing batch.
**Deletion semantics:** Expiry uses the documented hard-delete/privacy semantics: source write payload scrubbed, derived rows removed, WAL checkpoint attempted. It is distinct from writer revocation, which preserves source write events for audit. There is no separate expiry event type: each expired item is represented by the existing `delete` event, so replay behavior and deletion tooling remain consistent. Repeating the sweep is idempotent.
**Why:** M1's lifecycle definition required a real retention/expiry operation, while the existing decay-based lifecycle only reported candidates and did not mutate state. Event creation time provides a stable retention clock that avoids treating a fact's historical `valid_from` date as its storage-retention age.
**Affects:** `src/agm/models.py`, `src/agm/store.py`, `src/agm/__init__.py`, M0/M1 lifecycle tests and docs. No new dependency, REST path, MCP tool, or CLI command is added; frozen external adapter contracts remain unchanged.
